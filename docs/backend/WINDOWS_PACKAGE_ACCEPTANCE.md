**Дата: 12 октября 2026. Итог: версия 0.1.0 принята пользователем, согласованный объём разработки завершён.** MSI получен, сверен и установлен на втором физическом Windows-ПК; оба ярлыка открыли клиент со встроенным runtime. После передачи приложения для ручной проверки пользователь подтвердил, что всё работает, и попросил подготовить финальный PR.

Реализация упаковки объединена в PR #23: `main` `8b4d9d7`, desktop-коммит `95e36d7`. Этот документ готовится в `feat/windows-package-acceptance`. Push и создание PR выполняет пользователь; публикация MSI отдельно не разрешалась.

## Финальное подтверждение пользователя

После проверки установки и передачи следующего шага — входа обоих участников из установленных клиентов — пользователь сообщил: **«короче все работает»** и предложил считать проект завершённым. Это **USER_REPORTED: общее ручное подтверждение работоспособности и принятие версии владельцем**.

Отдельного пошагового протокола HTTPS/WSS, восстановления комнаты, сетевой ошибки или удаления через Параметры Windows в этом сообщении нет. Эти границы записаны как ограничения доказательств версии 0.1.0; дополнительная разработка по текущему запросу не планируется.

## Сценарий для повторной проверки

Исходный сценарий сохранён для будущих регрессионных прогонов и уточнения покрытия. Текущий объём работ закрыт по подтверждению пользователя; новые результаты можно добавить при отдельной проверке.

Проверять **тот же MSI** на обоих компьютерах. Закройте старые клиенты, запущенные через `run.ps1`, и используйте установленные ярлыки. Сам backend и PostgreSQL оставьте работать.

1. **Вход.** Оба участника открывают установленный клиент, проверяют один общий HTTPS-адрес и входят в разные аккаунты. Адрес вводится без `/api/v1` и без `:8090` для Tailscale Serve. [Инструкция подключения](SERVER_CONNECTION.md).
2. **Комната и сеть.** Создать комнату и войти по коду либо использовать текущую тестовую комнату. Каждый добавляет/меняет свою задачу; другой видит изменение без кнопки обновления. Зафиксировать результат обоих участников. Сам по себе ответ `401` на HTTP probe эту проверку не заменяет.
3. **FOCUS и восстановление.** Создатель запускает FOCUS. Второй участник закрывает только свой клиент, открывает ярлыком и входит снова. Проверить восстановление комнаты, задач и текущего таймера, затем правку задачи в обе стороны.
4. **Итог.** Завершить FOCUS, сравнить время/задачи в результате и убедиться, что появилась одна запись истории у каждого.
5. **Недоступность.** В одном установленном клиенте временно указать заведомо недоступный локальный адрес, например `http://127.0.0.1:1`, и попытаться войти. Должно появиться понятное сообщение о сети без перехода на демоданные. Вернуть прежний HTTPS-адрес, войти и проверить комнату. Переключение сервера очищает локальную авторизацию.
6. **Удаление и повторная установка на втором ПК.** Закрыть установленный клиент, удалить через Параметры Windows → Приложения → Установленные приложения. Проверить отсутствие EXE/runtime/обоих ярлыков. Установить тот же MSI заново, убедиться в отсутствии дублей, сохранённых адресе/username, пустом пароле и наличии прежней серверной истории после входа.

Результаты вносить только после выполнения: дата, какой компьютер, конкретный шаг, PASS/FAIL и наблюдение. Отчёт пользователя обозначать как ручную проверку участником. Не переносить сюда PASS из [предыдущей приёмки через `run.ps1`](REMOTE_ACCEPTANCE_2026-10-12.md).

Ранее проверенные длительное выключение backend, физический сон и весь цикл BREAK сохраняют свои отчёты и версии. Чистая Windows и обновление на новую версию остаются отдельными ограничениями. Файл MSI не опубликован; решение о публикации принимается пользователем отдельно от завершения разработки.
