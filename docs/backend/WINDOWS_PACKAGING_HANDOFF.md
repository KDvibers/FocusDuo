# Windows-установщик: задание Kotlin-разработчику

**Итог версии 0.1.0: согласованный объём упаковки завершён по решению владельца.** Windows x64 MSI реализован в PR #23 (`main` `8b4d9d7`); локальная установка, оба ярлыка, встроенный runtime, demo UI, удаление через Windows Installer и повторная установка проверены Kotlin-разработчиком. [Фактический протокол](../../desktop/docs/WINDOWS_PACKAGING.md). [Итоговая приёмка](WINDOWS_PACKAGE_ACCEPTANCE.md) фиксирует проверки установки/запуска на втором ПК и общее подтверждение пользователя без дополнительного пошагового протокола. Чистая Windows и другие непроверенные варианты не объявляются PASS. MSI не подписан и не опубликован.

Ниже сохранено **исходное задание до PR #23**. Его требования и описанная начальная основа не означают, что упаковка всё ещё отсутствует. Публикация MSI остаётся отдельным решением пользователя.

Совместная работа двух клиентов через один сервер подтверждена в [отчёте удалённой приёмки](REMOTE_ACCEPTANCE_2026-10-12.md). Теперь пользователь должен получать FocusDuo как обычное Windows-приложение: установить, открыть ярлыком, указать сервер и войти в аккаунт.

## Ответственность и результат

Kotlin-разработчик выполняет работу в `desktop/**`, в отдельной ветке, например `feat/desktop-windows-package`, и готовит изменения и описание отдельного PR. Push и создание PR выполняет пользователь. Backend-разработчик сопровождает [инструкцию подключения](SERVER_CONNECTION.md) и корневой README. Контракт V1 и серверная реализация на этом этапе не меняются.

Результат — реальный `.msi` либо `.exe`, собранный на Windows, с собственной иконкой, ярлыками на рабочем столе и в меню «Пуск», встроенным Java runtime и протоколом установки/запуска/удаления. Для первого пакета достаточно MSI; EXE можно добавить тем же этапом, но проверять каждый заявленный формат отдельно.

Бинарник остаётся локальным результатом сборки; в Git входят конфигурация, ресурсы, инструкция и свидетельства проверки. Push выполняет пользователь. GitHub Release и публикация файла для скачивания требуют отдельного указания пользователя.

## Основа перед упаковкой (до PR #23)

- `desktop/build.gradle.kts`: Kotlin/Compose Compiler **2.2.20**, Compose Multiplatform **1.9.1**, Gradle Wrapper **8.13**, Java toolchain **21**, Ktor/CIO **3.3.1**.
- Точка входа — `dev.focusduo.MainKt`. Сейчас `compose.desktop.application` содержит только `mainClass`: конфигурации `nativeDistributions` ещё нет.
- `desktop/run.ps1` запускает Gradle `run` с JDK 21. Он остаётся инструментом разработчика; установленное приложение не должно зависеть от него.
- В окне пока не задана собственная иконка. Логотип интерфейса — два пересекающихся зелёных круга в `FocusDuoLogo`; использовать его как основу единой иконки приложения.
- Адрес сервера уже редактируется в UI. Сохраняются только `baseUrl` и `rememberedUsername` в `%USERPROFILE%\.focusduo\preferences.properties`; пароль и bearer-токен остаются в памяти.
- Понятные ошибки сети уже реализованы. Их нужно проверить именно из установленного приложения, включая HTTPS и WSS.

## Что реализовать

### 1. Конфигурация пакета и ресурсы

Добавить `import org.jetbrains.compose.desktop.application.dsl.TargetFormat` и настроить `nativeDistributions` в существующем `compose.desktop.application`:

| Настройка | Требуемое значение или действие |
| --- | --- |
| `targetFormats(TargetFormat.Msi)` | Обязательный первый формат; `TargetFormat.Exe` — если тоже собирается и проверяется. |
| `packageName` | `FocusDuo`. |
| `packageVersion` | Числовая версия `MAJOR.MINOR.BUILD`; текущая версия проекта `0.1.0` подходит. |
| `description`, `vendor` | Описание FocusDuo и согласованный автор/команда без выдуманной организации. |
| `includeAllModules = true` | Рекомендуемая начальная конфигурация runtime; уменьшение допускается после проверки всех сетевых и UI-сценариев. |
| `windows.iconFile` | Настоящий `.ico` с несколькими размерами, сохранённый внутри `desktop/`. |
| `windows.shortcut = true` | Ярлык на рабочем столе. |
| `windows.menu = true`, `windows.menuGroup = "FocusDuo"` | Ярлык в меню «Пуск». |
| `windows.console = false` | Обычный запуск без консольного окна. |
| `windows.perUserInstall = true` | Рекомендуется установка для текущего пользователя; проверить без прав администратора. |
| `windows.dirChooser = true` | Возможность выбрать каталог установки. |
| `windows.upgradeUuid` | Создать один UUID для продукта и сохранить его неизменным для следующих версий. |

Эти свойства есть в [DSL Compose 1.9.1](https://github.com/JetBrains/compose-multiplatform/blob/v1.9.1/gradle-plugins/compose/src/main/kotlin/org/jetbrains/compose/desktop/application/dsl/PlatformSettings.kt). Не копировать параметры из примеров другой версии плагина без проверки.

Подключить ту же иконку к Compose `Window`, чтобы окно и панель задач соответствовали ярлыкам. [SVG для README](assets/focusduo-mark.svg) повторяет геометрию и цвета существующего `FocusDuoLogo` и может служить основой; это ещё не ICO для Windows. Исходник иконки и процедура получения ICO должны быть воспроизводимыми. Не заменять ресурс только внутри уже собранного бинарника.

### 2. Встроенный runtime и инструменты сборки

Собирать на **Windows x64 с JDK 21 x64** и записать фактические версии JDK, Windows и архитектуру. `jpackage`/`jlink` создают runtime внутри пакета; на целевом ПК не должны требоваться Java, Gradle или исходники. Сборка Windows-пакета из WSL/Linux не заменяет Windows-сборку. [Документация JDK 21](https://docs.oracle.com/en/java/javase/21/jpackage/packaging-overview.html).

Явно использовать JDK 21 для запуска Gradle/упаковки или задать `compose.desktop.application.javaHome`. Один `jvmToolchain(21)` не гарантирует этот выбор: в [Compose 1.9.1](https://github.com/JetBrains/compose-multiplatform/blob/v1.9.1/gradle-plugins/compose/src/main/kotlin/org/jetbrains/compose/desktop/application/internal/JvmApplicationData.kt) значение по умолчанию берётся из `java.home` процесса Gradle.

Для JDK 21 требуется WiX. Compose 1.9.1 умеет использовать каталог `WIX_PATH`; без него по умолчанию загружает WiX 3.11.2. Зафиксировать фактически использованный вариант, а не требовать от конечного пользователя установки WiX. [Поведение плагина](https://github.com/JetBrains/compose-multiplatform/blob/v1.9.1/gradle-plugins/compose/src/main/kotlin/org/jetbrains/compose/desktop/application/internal/wixToolset.kt).

Не включать в пакет `.env`, пароли, токены, локальные preferences, тестовые runtime, отчёты с секретами или базу данных. Сохранить необходимые уведомления и лицензии поставляемого JDK/runtime и зависимостей, включая уже имеющуюся `desktop/src/main/resources/fonts/OFL.txt` для Manrope. Не назначать проекту лицензию без решения владельцев.

### 3. Сборка и проверка образа

После добавления конфигурации выполнить из `desktop/` при выбранном Windows JDK 21:

```powershell
.\gradlew.bat --version
.\gradlew.bat check --console=plain
.\gradlew.bat createDistributable --console=plain
.\gradlew.bat runDistributable --console=plain
.\gradlew.bat packageMsi --console=plain
```

Если заявлен EXE, отдельно выполнить `packageExe`. Выходные файлы находятся под `desktop/build/compose/binaries/`; записать точный путь и имя фактически созданного пакета. Эти команды — задание на будущий прогон, а не уже выполненные проверки.

Обычный `run` использует полный runtime и не доказывает работоспособность упакованного приложения. Для анализа состава JDK у версии **1.9.1** есть задача **`suggestRuntimeModules`**: это точное имя из [исходника плагина](https://github.com/JetBrains/compose-multiplatform/blob/v1.9.1/gradle-plugins/compose/src/main/kotlin/org/jetbrains/compose/desktop/application/internal/configureJvmApplication.kt). Статический анализ не заменяет проверку динамически загружаемых классов и провайдеров.

Если позже сокращать runtime, проверить шрифты/кириллицу, clipboard, Compose/Skiko и реальные HTTPS/WSS. В частности, модуль [`jdk.crypto.ec`](https://github.com/openjdk/jdk21u/blob/master/src/jdk.crypto.ec/share/classes/module-info.java) предоставляет SunEC; отсутствие криптографического провайдера может проявиться только при TLS-соединении. Не отключать проверку сертификатов ради успешного теста.

### 4. Подключение к серверу

Установщик поставляет **desktop-клиент и его Java runtime**. Backend и PostgreSQL работают отдельно, на одном общем сервере; их не нужно устанавливать каждому участнику.

Сохранить существующий UI выбора адреса: только базовый адрес вида `https://имя-сервера`, без `/api/v1` и `/ws`. Не зашивать личный Tailscale-домен в сборку. Для локальной разработки остаётся `http://127.0.0.1:8090`; на компьютере друга этот адрес означает его собственный ПК. Подробности — в [инструкции подключения](SERVER_CONNECTION.md).

При запуске без сервера должны оставаться доступны настройки адреса и понятная ошибка подключения. Real-режим не переключается в демо автоматически. После перезапуска ожидается повторный вход, затем восстановление текущей комнаты; не добавлять сохранение пароля или токена на диск для удобства установщика.

## Приёмка установленного приложения

Проводить на Windows без отдельной установки Java/Gradle, например в чистой тестовой VM. Запуск на машине разработчика дополнить проверкой используемого встроенного runtime; удаления установленного системного JDK не требуется. Если чистая среда недоступна, обозначить эту проверку как незапущенную.

| Проверка | Ожидаемый результат |
| --- | --- |
| Установка MSI/EXE | Приложение устанавливается выбранным способом; видны корректные имя и версия. Для `perUserInstall` проверить обычного пользователя. |
| Ярлыки и ресурсы | Запуск с рабочего стола и через «Пуск»; правильные иконки окна/панели задач; кириллица и Manrope отображаются. |
| Самостоятельный запуск | Закрыть Gradle и терминалы разработки; приложение работает из установленного каталога со своим runtime. |
| Адрес и недоступный сервер | Ввод/сохранение адреса через UI; понятная ошибка при недоступности; после исправления адреса возможен вход. |
| HTTPS/WSS | Два установленных клиента подключаются к общему серверу: вход, create/join, изменение задачи в обе стороны, FOCUS и завершённый итог. |
| Повторный запуск | Несекретные настройки сохранились; требуется вход, после него восстановлена текущая комната. |
| Регрессия UI | Окна 1280×800 и 1000×700, прокрутка, клавиатурный фокус, длинные русские строки, состояния загрузки/ошибки. |
| Удаление | Через настройки Windows удаляются приложение/runtime и его ярлыки. Backend, PostgreSQL и серверная история не затрагиваются. |
| Повторная установка / обновление | Нет дублирующихся ярлыков или параллельных копий одной версии; установленное поведение настроек документировано. |

Несекретные `%USERPROFILE%\.focusduo\preferences.properties` рекомендуется сохранять при обновлении и обычном удалении. Не удалять пользовательский каталог автоматически без явного выбора пользователя. В инструкции указать, что сохраняется, где находится и как удалить отдельно при необходимости. Проверять установку/удаление на тестовой копии приложения, не подменяя рабочую пользовательскую сессию.

## Что включить в PR и передачу

1. Конфигурацию native distributions, иконку/исходник, при необходимости скрипт упаковки внутри `desktop/`.
2. Актуальные `desktop/README.md`, `desktop/docs/ROADMAP.md` и `desktop/docs/HANDOFF.md`; при необходимости отдельный протокол Windows-приёмки.
3. Коммит сборки, состояние рабочей копии, Windows/JDK/архитектуру, выполненные команды, результаты и незапущенные проверки. Предыдущие 199 тестов не выдавать за новый прогон.
4. Реальные скриншоты установки, ярлыка/окна, настройки сервера/ошибки и удаления; без паролей и токенов.
5. Точное имя пакета, размер и SHA-256, а также фактический статус цифровой подписи. Не заявлять подписанный пакет без проверки.
6. Локальное расположение бинарника для передачи владельцу; никаких автоматических публикаций. Проверяющий должен установить именно файл с записанным SHA-256.

Этап завершён после получения пакета и фактической приёмки установки, запуска ярлыками, подключения и удаления. Успешная сборка сама по себе не закрывает этот этап. После этого FocusDuo можно обозначить готовым Windows MVP для использования с доступным общим backend; публичный хостинг и публикация установщика остаются отдельными действиями.
