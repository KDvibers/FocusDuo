# Подключение FocusDuo к общему серверу

Оба клиента должны обращаться к **одному backend**. Учётные записи, комнаты и история принадлежат выбранному серверу. Если каждый запустит собственную базу и backend, совместной комнаты между ними не будет.

Клиент доступен как собранный **Windows x64 MSI 0.1.0** со встроенным Java runtime и как запуск из исходников через `desktop/run.ps1`. Установленный клиент открывается ярлыком; настройки адреса одинаковы для обоих способов запуска. Версия 0.1.0 завершена в согласованном объёме по решению владельца. Локальные проверки MSI записаны в [протоколе упаковки](../../desktop/docs/WINDOWS_PACKAGING.md), проверки второго ПК и общее подтверждение пользователя без дополнительного пошагового протокола — в [итоговом отчёте](WINDOWS_PACKAGE_ACCEPTANCE.md). MSI не подписан; публичного файла для скачивания пока нет.

## Что делает каждый участник

**Владелец сервера** запускает PostgreSQL и Java backend по [инструкции](../../backend/README.md), обеспечивает доступ к нему и передаёт партнёру адрес. `.env` и пароль PostgreSQL остаются на сервере.

**Оба участника** запускают клиент, задают этот адрес и входят каждый в свой аккаунт FocusDuo. Если аккаунт был создан на другом backend, на общем сервере потребуется регистрация.

Для удалённой работы серверный компьютер должен оставаться включённым, с работающими backend и БД. Если он уснул, установка клиента у партнёра не восстановит доступ к выключенному серверу. После запуска сервера клиент сможет синхронизироваться; истёкшая сессия потребует нового входа.

## Адрес в приложении

На экране входа откройте «Адрес сервера и имя»; после входа адрес доступен в «Настройках».

| Где работает backend | Что указывать |
| --- | --- |
| На этом же компьютере | `http://127.0.0.1:8090` |
| В одной локальной сети | Например, `http://192.168.1.20:8090`; требуется доступный LAN-порт сервера |
| Через Tailscale Serve | HTTPS-адрес, который напечатала команда `serve`, без `:8090` |
| На другом настроенном HTTPS-сервере | Его адрес с корректным сертификатом и поддержкой WebSocket |

Вводите только `http://` или `https://`, имя узла и при необходимости порт. Не добавляйте `/api/v1`, `/ws/rooms/...`, логин, пароль, токен или параметры запроса. Клиент сам выбирает REST-путь и `ws://`/`wss://` для WebSocket.

Смена сервера очищает локальную сессию и требует нового входа. Серверная комната прежнего аккаунта при этом не закрывается. Адрес и username сохраняются в `%USERPROFILE%\.focusduo\preferences.properties`; пароль и токен остаются в памяти.

Переменная `FOCUSDUO_BASE_URL` имеет приоритет над сохранённым адресом при любом способе запуска. Если приложение возвращается к неожиданному серверу, проверьте эту переменную в окружении запуска. Полезные команды и точный порядок настроек описаны в [Desktop README](../../desktop/README.md#адрес-сервера-и-локальные-настройки).

## Удалённое подключение через Tailscale

Этот маршрут прошёл [ручную проверку на двух компьютерах](REMOTE_ACCEPTANCE_2026-10-12.md). Её подробный протокол относится к запуску через `run.ps1`; сведения об установленном пакете и итоговое подтверждение пользователя записаны [отдельно](WINDOWS_PACKAGE_ACCEPTANCE.md).

### 1. Подготовить сеть

Установите Tailscale на оба компьютера и подключите их к одной tailnet. Убедитесь, что политика доступа разрешает партнёру обращаться к серверной машине. В этой схеме используется **Serve**, доступный внутри tailnet. [Документация Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve).

### 2. Проверить backend на серверном компьютере

Владелец запускает backend по [Backend README](../../backend/README.md). Для Serve оставьте `SERVER_ADDRESS=127.0.0.1` и `SERVER_PORT=8090`. PostgreSQL остаётся на локальном порту 5434.

Из Windows PowerShell на серверном компьютере:

```powershell
curl.exe -i --max-time 15 http://127.0.0.1:8090/api/v1/me
```

Ожидается **HTTP 401** с JSON-кодом `UNAUTHORIZED`: запрос не содержит токена. Это подтверждает доступность HTTP-маршрута; работа БД и WebSocket проверяется входом и синхронизацией комнаты. Если backend работает в WSL, сначала добейтесь ответа именно из Windows; особенности запуска с IPv4 описаны в Backend README.

### 3. Включить HTTPS-прокси

На Windows-компьютере, где доступен локальный backend, из PowerShell:

```powershell
& 'C:\Program Files\Tailscale\tailscale.exe' serve --bg --https=443 http://127.0.0.1:8090
& 'C:\Program Files\Tailscale\tailscale.exe' serve status
```

Если Tailscale предложит включить Serve/HTTPS, владелец tailnet открывает показанную ссылку и выполняет настройку, затем повторяет команду при необходимости. Скопируйте выданный **HTTPS-адрес** и передайте его партнёру. `--bg` сохраняет работу Serve в фоне; сам Java backend эта команда не запускает. [Параметры команды](https://tailscale.com/docs/reference/tailscale-cli/serve).

### 4. Проверить маршрут с компьютера партнёра

На втором компьютере с включённым Tailscale:

```powershell
$focusDuoUrl = Read-Host 'Вставьте HTTPS-адрес из tailscale serve status'
curl.exe -i --max-time 15 "$($focusDuoUrl.TrimEnd('/'))/api/v1/me"
```

Ожидается тот же `401 UNAUTHORIZED`. Сертификат должен приниматься обычной проверкой TLS.

### 5. Подключить приложения

Оба указывают один выданный HTTPS-адрес в настройках FocusDuo, входят и создают/объединяют комнату. Каждый добавляет свою задачу: она должна автоматически появиться у другого без ручного обновления. Затем создатель запускает FOCUS; оба сверяют состояние раунда.

Учётная запись Tailscale даёт сетевой доступ. Вход в FocusDuo по username/password выполняется отдельно.

## Если сервер недоступен

| Наблюдение | Что проверить |
| --- | --- |
| «Не удалось связаться с сервером. Проверьте адрес и подключение.» | Правильный адрес, запущенный backend, доступность сети/Tailscale. Начните с локального HTTP-запроса на серверной машине, затем проверьте удалённый адрес. |
| «Сервер не ответил вовремя. Повторите попытку.» | Соединение и состояние backend; повторите попытку после восстановления. |
| Локальный запрос работает, удалённый — нет | Tailscale на обоих компьютерах, адрес из `serve status` и права доступа в tailnet. |
| Вход успешен, задачи у партнёра не обновляются | Оба в одной комнате одного сервера; прокси поддерживает WebSocket Upgrade и передачу Authorization. |
| После перезапуска клиента снова нужен пароль | Это ожидаемо: пароль и токен не сохраняются на диск. После входа восстановится текущая комната. |
| В истории нет прежних сессий | Проверьте аккаунт и адрес backend: история хранится на сервере и относится к участникам раундов. |
| Ошибка сертификата HTTPS | Проверьте адрес, системные дату/время и сертификат сервера. Не отключайте проверку TLS. |

При сетевом сбое реальный режим не переключается на демоданные. До актуализации состояния изменения комнаты блокируются. При неоднозначном результате команды используйте предложенный клиентом повтор: он сохраняет исходный ключ запроса.

## Запуск установленного клиента

Установите переданный MSI → откройте FocusDuo ярлыком → настройте адрес в приложении → войдите → создайте комнату или присоединитесь по коду. Клиент содержит собственный runtime; Java, Gradle, PowerShell и серверный `.env` для запуска клиента не нужны.

Установка, запуск ярлыками и встроенный runtime подтверждены на двух ПК в объёме [отчёта](WINDOWS_PACKAGE_ACCEPTANCE.md). Владелец подтвердил работу приложения и завершение 0.1.0; отдельный новый пошаговый протокол сетевых действий из установленного клиента не составлялся. Для повторения проверки открывайте именно установленное приложение, чтобы запуск через Gradle не подменял проверку MSI. SHA-256 артефакта и непроверенные варианты сохранены в отчёте.
