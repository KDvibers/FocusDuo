# FocusDuo Desktop — текущая передача

## Статус на 10 октября 2026

**Этап 5 из 10 реализован:** `RealRepository`, Ktor/CIO, DTO V1, настоящие формы входа/регистрации, logout и восстановление профиля и текущей комнаты. Этапы 1–4 сохраняются; [план всей desktop-части](ROADMAP.md) разделяет оставшиеся команды, WS, reconnect, интеграцию и упаковку.

По прямому уточнению пользователя запуск и проверка Compose-окна, новые скриншоты, адаптация размеров и клавиатурный аудит нового интерфейса **отложены до этапа 7**. Сейчас проверяются компиляция и автоматические сценарии. Скриншоты этапов 2–3 сохранены как свидетельства прежних проверок и не подтверждают новые экраны этапов 4–5.

## Добавлено на этапе 5

- Ktor Client/CIO 3.3.1 и kotlinx.serialization 1.9.0, serializable DTO общего V1, отдельные mappings в domain. Полные снимки комнаты, ошибки, история и raw `ROOM_SNAPSHOT` имеют транспортные модели; наличие DTO истории/события ещё не означает подключение их HTTP/WS-потоков. Mappings отвергают неизвестные enum, некорректные UUID и даты; единицы миллисекунд и Long revision сохраняются.
- `RealRepository`: POST register/login/logout, GET `/me`, `/rooms/current` и чтение известной комнаты. `expiresAt` приходит с сервера, непрозрачный access token находится только в памяти. Пароль передаётся без trim/смены регистра; username/displayName нормализуются по V1. Строковое представление credential/session DTO скрывает пароль и токен.
- Без `--demo` открывается вход на выбранный backend. Демо остаётся отдельным явным режимом с `FakeRepository`; даже недоступный сервер не активирует его автоматически. URL можно изменить до входа и в настройках авторизованного режима.
- После успешной авторизации отдельно восстанавливаются профиль и текущая комната. Ошибка GET оставляет сессию и кнопку повтора, без повторного POST регистрации/входа. Серверная комната показывается для чтения; копирование кода и приглашение работают локально. Создание/вход по коду, задачи, таймерные команды, история и WS пока недоступны в реальном режиме и обозначены как следующий этап.
- `401` очищает token/room и возвращает к входу. Logout вызывает сервер и всегда очищает локальные credentials; при сетевой ошибке сообщается, что сервер мог не отозвать токен. Выход, смена адреса и закрытие приложения не вызывают закрытие комнаты. Смена адреса отменяет прежние запросы и блокирует применение их поздних результатов.
- Транспорт использует bearer только в Authorization, не следует redirect и не логирует HTTP-содержимое. Ошибки сети, таймаута, протокола и контрактные коды имеют безопасные сообщения; произвольные HTML/stack trace/ответы сервера не выводятся. Ошибки полей авторизации привязываются к разрешённым полям формы.
- Все 10 общих fixtures скопированы без изменений в `src/test/resources/contracts/`, SHA-256 совпадает с исходниками. Desktop-тесты не требуют backend, общей папки fixtures или серверной сборки. Добавлены тесты DTO/HTTP/controller и настоящий TCP-сценарий production CIO с локальным тестовым HTTP-сервером.
- Явная задача `backendAuthSmoke` проверяет register → `/me` → current room → logout → login → восстановление → logout на запущенном Java backend. Она исключена из обычного `test` и на этом этапе не запускалась: на `127.0.0.1:8090` backend не был доступен.

Из корня репозитория:


## Добавлено на этапе 4

- Формы входа и регистрации в той же светло-зелёной дизайн-системе: username, displayName при регистрации, пароль с маскировкой и показом, ошибки полей и pending-состояние. Требования V1 проверяются локально; пароль не trim-ится.
- Явный деморежим с локальными аккаунтами. Можно войти в публичный пример `demo_user` / `FocusDuoDemo1!` либо зарегистрировать демоаккаунт. Это локальная симуляция авторизации, без REST и bearer-сессии сервера. В памяти хранятся соль и хеш демопароля; пароль не записывается в preferences.
- Полная навигация между главной, комнатой, историей, деталями итога и настройками. Главная предлагает создание/вход, текущую комнату и последний результат; выход из аккаунта не закрывает комнату и не удаляет её историю в текущем процессе.
- Список последних максимум 50 результатов, локальные фильтры «Все» / «Фокус» / «Перерыв», дата окончания с подписью часового пояса, фактическое активное время, плановая длительность и счётчики сохранённых задач участников. Отмена, досрочное завершение и завершение по времени различаются явно. Список не является статистикой за всё время.
- Подробный результат открывается из истории и позволяет вернуться к списку. Данные целей и задач берутся из замороженного `HistoryItem`, а не из текущей комнаты.
- Пустая история, пустой фильтр, загрузка и ошибка с повтором. Loading/error доступны через явные инструменты демо, чтобы проверить состояния без сервера; они не обозначают настоящую сетевую ошибку.
- Настройки сохраняют только несекретные адрес сервера и username в `%USERPROFILE%\.focusduo\preferences.properties`. Поддержаны default `http://127.0.0.1:8090`, приоритет `FOCUSDUO_BASE_URL`, проверка адреса и явный logout. Смена URL завершает текущий демовход и изолирует локальные аккаунты по адресу; демоданные серверу не отправляются. HTTP-реализация запланирована на этап 5.
- Незавершённый ввод настроек и форм не перезаписывается при обновлении комнаты. Автоматический итог открывается только на главной/в комнате без активного диалога; на остальных экранах показывается уведомление и новый результат становится доступен в истории. Ограничения длины auth/profile/goal/task согласованы по Unicode code points.

## База из этапов 1–3

- Самостоятельная desktop-сборка: Kotlin/JVM 2.2.20, Compose Desktop 1.9.1, Gradle Wrapper 8.13 с SHA-256 и Java toolchain 21. PowerShell-скрипт находит JDK 21 без изменения постоянных системных настроек.
- Светло-зелёные компоненты Compose, Manrope с кириллицей, согласованные Canvas-иконки, системная рамка Windows. Комната сохраняет круговой таймер слева, участников под ним и карточки задач справа; узкое окно использует одну колонку и прокрутку.
- Явное включение демо через `--demo` или стартовый экран. В заголовке окна и интерфейсе видна пометка режима; серверные соединения не создаются.
- `FocusDuoRepository`, локальный `FakeRepository` и `StateFlow`. Изменения сериализуются через `Mutex`; снимки и история содержат неизменяемые списки.
- Создание пустой комнаты, вход в подготовленный пример `FD-DEMO42`, приглашение и копирование кода через clipboard. Локальный пример открывается от имени обычного участника; для управления таймером можно переключиться на создателя.
- Собственная цель до 240 символов; добавление, редактирование, отметка и удаление собственных задач. Название после trim содержит 1–160 символов; максимум 20 задач у каждого участника. Чужие задачи доступны только для чтения, в том числе владельцу комнаты.
- Настройки длительности: фокус 5–180, перерыв 1–60 целых минут. Их меняет только создатель вне RUNNING/PAUSED.
- FOCUS запускается владельцем при двух участниках и отсутствии активного раунда. BREAK запускается отдельно после текущего COMPLETED FOCUS. Следующий рабочий раунд тоже запускается вручную.
- Отсчёт и круговой прогресс связаны со снимком репозитория. В демо монотонные часы защищают отсчёт от коррекции системного времени; UI регулярно запрашивает свежий снимок. Обычные тики обновляют временные поля без изменения revision.
- Пауза замораживает остаток и активное время, продолжение сохраняет исходный startedAt и устанавливает новый срок из остатка. Только владелец управляет раундом. Команды адресуют конкретный текущий roundId.
- Ручное завершение фиксирует COMPLETED/MANUAL и фактическое активное время без пауз. Автозавершение фиксирует COMPLETED/ELAPSED с endedAt, равным сроку окончания даже при поздней обработке. Завершение и историю создаёт `FakeRepository`, а не круговой индикатор.
- Итог показывает тип раунда, реальное активное время, плановую длительность, цели, задачи и счётчики обоих. У досрочного завершения, окончания по времени и отмены разные подписи. История фиксирует копию один раз по roundId; дальнейшие изменения задач, целей и имён не меняют старый результат.
- Явное закрытие комнаты с подтверждением доступно обоим. Активный раунд становится CANCELLED/ROOM_CLOSED; уже завершённый результат сохраняется. Закрытая комната доступна для просмотра, её изменения запрещены; на главной можно создать новую комнату. Закрытие окна является отдельным действием приложения.
- В состоянии хранятся последние 50 результатов по endedAt и roundId. На этапе 3 был доступен отдельный итог; этап 4 добавляет общий список и детали. Это не статистика за всё время.
- Инструменты демо: присоединение партнёра, смена точки зрения, локальное имя, сброс с подтверждением, продвижение демочасов «+1 минута» и «До окончания раунда» во время RUNNING. Они не расширяют API и не отправляются серверу.

## Решения и границы

Рабочая ветка — `feat/desktop-mvp`, исходная база этапа 5 — пользовательский коммит `d83b240` с результатом этапа 4. Изменения этого этапа находятся только внутри `desktop/**`; backend и общие файлы не меняются. Новые коммиты и удалённые push/merge/publish агентом не выполнялись.

Окончательный дизайн — [последний светло-зелёный макет пользователя](design/light-green-reference.png). Он заменяет тёмную тему из исходного ТЗ и общих `docs/design/`; контракт V1 сохраняется. Справочные копии полного ТЗ и контракта находятся в `desktop/docs/reference/`.

Демо моделирует локальный сервер и второго участника в одном процессе. Статус «В фокусе» определяется активным раундом; он не является online-присутствием или измерением внимания. Сброс демо удаляет локальную комнату и историю; закрытие комнаты сохраняет результат. Logout сохраняет деморепозиторий аккаунта и активный раунд до закрытия процесса. Реальный режим выполняет только описанные выше HTTP-вызовы; закрытие приложения, logout, смена URL и потеря сети не отправляют команду закрытия комнаты.

Общие [backend HANDOFF](../../docs/backend/HANDOFF.md) и [план совместной приёмки](../../docs/backend/INTEGRATION.md) прочитаны. Их «третий этап» относится к серверной подготовке и реальной интеграции, тогда как выполненный desktop-этап 3 добавлял локальный демо-таймер. Успешные серверные HTTP/WS-проверки не подтверждают работу Kotlin-клиента; клиентские mock/CIO-проверки этапа 5 также не подтверждают совместную Java-интеграцию, WS, reconnect или LAN.

## Точные ограничения

1. Демоаккаунты, хеши демопаролей, комнаты и результаты хранятся только в памяти одного процесса. Перезапуск удаляет их; сброс удаляет комнату и результаты текущего демоаккаунта. Второй участник моделируется локально. Работа двух реальных клиентов ещё не реализована.
2. Реальная авторизация реализована и проверена mock/TCP-сценариями, но совместный запуск с Java backend ещё не выполнен. Preferences сохраняют лишь URL и username; токен/пароль не сохраняются. Изменение имени в демо не является серверным редактированием профиля. На перезапуске нужен новый вход, refresh-token в V1 нет.
3. Реальный режим пока восстанавливает комнату для чтения и обновляет её только вручную. REST-команды комнаты/цели/задач/раундов, реальная история и raw WebSocket остаются этапом 6; reconnect, идемпотентность, revision conflict и восстановление после сна — этапом 7. Реальный таймер показывает поля последнего HTTP-снимка и пока не выполняет живой отсчёт. Достижение нуля UI не создаёт серверную историю.
4. Все 10 JSON-fixtures проверены; Java backend, два реальных клиента и LAN пока не проверялись. `backendAuthSmoke` подготовлен и исключён из обычного `test`, но не запускался без доступного backend. Монотонные демочасы не подтверждают синхронизацию настоящего клиента после сна или разрыва сети. История V1 ограничена последними 50 раундами без пагинации.
5. Новые экраны этапов 4–5 ещё не проверены запуском Compose: по просьбе пользователя этот аудит отложен до этапа 7. Полный аудит доступности и заключительная визуальная регрессия остаются в этапе 9. Используется системная рамка Windows; упаковка `.msi`/`.exe`, установка и подпись ещё не выполнены. Bash-команды README не проверялись на Linux/macOS.

## Коммит, push и PR

После просмотра результата выполнить в PowerShell по очереди. Если команда завершилась ошибкой, следующую не выполнять:

```powershell
Set-Location "C:\Users\user\Desktop\focusDuo"
git add -- desktop
git diff --cached --stat
git commit -m "feat(desktop): connect Ktor backend authentication"
git push -u origin feat/desktop-mvp
```

Перед коммитом убедиться по списку staged-файлов, что включены только нужные desktop-изменения. Push отправляет рабочую ветку, без слияния в `main`. [Заголовок и описание PR этапа 5](PR_STAGE_5.md).
