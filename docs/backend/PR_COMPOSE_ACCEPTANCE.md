# docs(integration): record two-client Compose and Windows sleep acceptance

После исправления wake проверка двух настоящих Compose-окон с Java и физическим сном оставалась открытой. Теперь ручной прогон M1–M4 подтвердил общую комнату и роли, сохранение PAUSED/RUNNING после двух сеансов Windows Modern Standby, неизменяемый итог FOCUS и закрытие комнаты с сохранением BREAK.

Добавлены [COMPOSE_ACCEPTANCE.md](COMPOSE_ACCEPTANCE.md) и 29 реальных снимков обоих клиентов. В отчёте указаны commits, среда, события питания и временные замеры; команды воспроизведения остаются в [MANUAL_ACCEPTANCE.md](MANUAL_ACCEPTANCE.md). Production Java/Kotlin, контракт и fixtures не менялись.

## Проверено

- Два независимых Compose-процесса, desktop `8fdb392` → настоящий WSL Java на `127.0.0.1:8090` → постоянная PostgreSQL 17.11 на 5434; `.env` сохранён.
- PAUSED: Modern Standby **73.5048001 с**, оба остатка **24:45** до/после, последующая правка задачи A видна B.
- RUNNING: Modern Standby **117.0503097 с**; между наблюдениями A отсчёт уменьшился на 208 с за 207.603 с календарного времени, B — на 207 с за 207.235 с. Java PID и БД сохранились; ручных refresh/relogin/restart не было.
- Одинаковый FOCUS/MANUAL **4 мин 31 сек** у обоих; редактирование задачи после завершения сохранило исторический текст и статус. BREAK/CANCELLED/ROOM_CLOSED **37 секунд**, оба CLOSED, история по **2 из 2**, команды комнаты отключены.
- Read-only SQL собственной комнаты подтвердил CLOSED/revision 16, **2 раунда / 2 истории без дублей**, 0 active memberships и 0 неотозванных сессий двух тестовых пользователей. Точное активное время: FOCUS **271241 мс**, BREAK **37026 мс**; историческая задача FOCUS сохранила исходный текст/статус, живая задача и BREAK — позднюю правку.
- Оба пользователя вышли; окна оставлены на экране входа. Обычные Java backend и PostgreSQL продолжают работать, данные и `.env` сохранены.
- `git diff --check` и локальные ссылки изменённой документации проверены. Все 29 JPG совпадают по SHA-256 с исходными снимками; `desktop/**` и исполняемый backend не изменены.

## Ограничения

Foreground-активация окон могла запускать восстановление; heartbeat-only/WS-only путь, остановка `nanoTime` и точная recovery latency не измерены. Это два конкретных сеанса Modern Standby, без заявления о всех режимах сна Windows. LAN, отключение адаптера, TTL, просроченный ELAPSED, полная UI-регрессия и упаковка ещё открыты; backend-этап 3 не закрывается.

Полный Maven `verify`, Gradle-тесты и harness для этой документационной проверки не перезапускались. Предыдущие 185 + 2 теста и четыре harness перечислены отдельно в [WAKE_ACCEPTANCE.md](WAKE_ACCEPTANCE.md). CI этой ветки до push владельца не запускался. Следующий checkpoint — review отчёта и согласование оставшейся совместной приёмки; автоматические push/merge не выполняются.
