# FocusDuo Desktop

Kotlin/JVM + Compose Desktop для Windows. Самостоятельная сборка: backend не нужен для сборки или запуска этого каталога.

## Текущий результат: этап 3 из 10

Рабочая локальная комната со светло-зелёным оформлением: `FocusDuoRepository`, `FakeRepository`, состояние через `StateFlow`, участники, цели и собственные задачи. Добавлены раунды FOCUS/BREAK, отсчёт, пауза, продолжение, ручное и автоматическое завершение, закрытие комнаты и итог с замороженными целями и задачами. Итог различает окончание по времени, досрочное завершение и отмену при закрытии комнаты. Этап 3 завершён: 35 тестов прошли; реальный Compose-интерфейс проверен на Windows, сохранены 13 скриншотов. Фактические результаты и ограничения — в [HANDOFF](docs/HANDOFF.md).

Демо включается только флагом `--demo` или кнопкой на стартовом экране и имеет постоянную пометку. Данные находятся в памяти и сбрасываются при закрытии приложения. Сетевых запросов сейчас нет. Таймер и завершение принадлежат локальному `FakeRepository`; это не проверка серверного таймера или совместной работы двух приложений.

## Запуск в PowerShell

Из корня репозитория:

```powershell
# Первый запуск скачивает зависимости. Скрипт ищет JDK 21 в FOCUSDUO_JAVA_HOME,
# JAVA_HOME, затем в пользовательской .jdks и по java из PATH.
powershell -ExecutionPolicy Bypass -File .\desktop\run.ps1 -Demo
```

`ExecutionPolicy Bypass` относится только к этому процессу PowerShell; скрипт не меняет системную политику или постоянные переменные среды. Без `-Demo` откроется экран явного выбора демо:

```powershell
powershell -ExecutionPolicy Bypass -File .\desktop\run.ps1
```

Если автоматический поиск JDK не сработал:

```powershell
$env:FOCUSDUO_JAVA_HOME='C:\путь\к\jdk-21'
powershell -ExecutionPolicy Bypass -File .\desktop\run.ps1 -Demo
```

Прямой запуск и тесты через wrapper:

```powershell
$env:JAVA_HOME='C:\путь\к\jdk-21'
Set-Location desktop
.\gradlew.bat test
.\gradlew.bat run --args="--demo"
.\gradlew.bat run --args="--demo --width=1000 --height=700"
```

Для проверки размера окна также доступно `run.ps1 -Demo -Width 1000 -Height 700`. Свернуть, развернуть, переместить и закрыть окно можно стандартными средствами Windows.

## Что проверить в демо

1. На главной нажать «Создать комнату»: по умолчанию 25 минут фокуса и 5 минут перерыва. Новая комната содержит одного участника, пустые цель и задачи.
2. Изменить свою цель, добавить задачу, отредактировать её, отметить выполнение и удалить. Цель — до 240 символов; название задачи — 1–160 после удаления пробелов по краям; максимум 20 задач у каждого участника.
3. Скопировать код кнопкой в заголовке или открыть «Пригласить». Код попадает в системный буфер обмена; внешние приглашения не отправляются.
4. В блоке «Управление демо» нажать «Добавить демоучастника», затем «Сменить участника». Собственная карточка меняется вслед за выбранным пользователем; чужие задачи доступны только для чтения. Роль создателя остаётся привязанной к владельцу комнаты.
5. От имени создателя изменить длительности: фокус 5–180 целых минут, перерыв 1–60. Настройки доступны только вне активного раунда; другой участник не может их менять.
6. Для готового примера использовать «Открыть пример комнаты» на главной или «Войти по коду» с `FD-DEMO42`. Регистр и пробелы по краям кода не важны. Неизвестный код показывает ошибку.
7. От имени создателя нажать «Начать фокус». Для запуска нужны два участника. У подготовленного примера создатель — другой участник: сначала нажать «Сменить участника» в инструментах демо.
8. Проверить отсчёт, «Пауза» и «Продолжить». На паузе остаток заморожен, её время не входит в итог. Только создатель управляет раундом; у другого участника соответствующие действия недоступны.
9. Завершить раунд вручную и проверить итог с фактическим активным временем, целями, задачами и счётчиками обоих. Вернуться в комнату, изменить задачу и открыть итог снова: сохранённая копия не меняется.
10. После завершённого FOCUS отдельно запустить «Начать перерыв». Следующий фокус тоже запускается вручную. Перерыв является отдельным раундом; повторный BREAK сразу после BREAK недоступен.
11. Для быстрой проверки автозавершения использовать явные инструменты демо «+1 минута» и «До окончания раунда» во время RUNNING. Они двигают только локальные демочасы, сохраняя допустимые длительности контракта. Итог по времени создаёт `FakeRepository`, а не круговой индикатор.
12. Нажать «Закрыть комнату» и подтвердить. Это доступно обоим участникам: активный раунд отменяется с отдельным итогом, завершённый результат сохраняется. Закрытая комната доступна для просмотра; на главной можно создать новую.
13. «Сбросить демо» с подтверждением удаляет локальную комнату, задачи и историю и возвращает на главную. Это инструмент демонстрации, отдельный от закрытия комнаты. Имя основного демопользователя сохраняется до закрытия приложения.

Имя редактируется в боковой панели, цель — в своей карточке комнаты; прежняя форма с предпросмотром этапа 1 заменена этими действиями. Главная и комната доступны через навигацию; переход на главную не удаляет комнату. Блок «Управление демо» находится под комнатой и при необходимости доступен прокруткой. Второй пользователь моделируется в одном процессе — это ещё не совместная работа двух приложений. Состояния подключения к серверу и online-присутствия не имитируются.

## Запуск в bash

```bash
export JAVA_HOME=/path/to/jdk-21
export PATH="$JAVA_HOME/bin:$PATH"
cd desktop
bash ./gradlew test
bash ./gradlew run --args='--demo'
```

Bash-команды приведены для разработки; проверка этого этапа выполняется на Windows. Java 21 требуется для разработки. Проверенного готового установщика пока нет.
