# FocusDuo Desktop — текущая передача

## Статус на 10 октября 2026

**Этап 4 из 10 реализован и проверен автоматическими тестами:** навигация, демоформы входа и регистрации, история с деталями и настройки. Этапы 1–3 завершены ранее; [план всей desktop-части](ROADMAP.md) сохраняет отдельные этапы для сети, интеграции и упаковки.

По прямому уточнению пользователя запуск и проверка Compose-окна, новые скриншоты, адаптация размеров и клавиатурный аудит нового интерфейса **отложены до этапа 7**. Сейчас проверяются компиляция и автоматические сценарии. Скриншоты этапов 2–3 сохранены как свидетельства прежних проверок и не подтверждают новые экраны этапа 4.

## Добавлено на этапе 4

- Формы входа и регистрации в той же светло-зелёной дизайн-системе: username, displayName при регистрации, пароль с маскировкой и показом, ошибки полей и pending-состояние. Требования V1 проверяются локально; пароль не trim-ится.
- Явный деморежим с локальными аккаунтами. Можно войти в публичный пример `demo_user` / `FocusDuoDemo1!` либо зарегистрировать демоаккаунт. Это локальная симуляция авторизации, без REST и bearer-сессии сервера. В памяти хранятся соль и хеш демопароля; пароль не записывается в preferences.
- Полная навигация между главной, комнатой, историей, деталями итога и настройками. Главная предлагает создание/вход, текущую комнату и последний результат; выход из аккаунта не закрывает комнату и не удаляет её историю в текущем процессе.
- Список последних максимум 50 результатов, локальные фильтры «Все» / «Фокус» / «Перерыв», дата окончания с подписью часового пояса, фактическое активное время, плановая длительность и счётчики сохранённых задач участников. Отмена, досрочное завершение и завершение по времени различаются явно. Список не является статистикой за всё время.
- Подробный результат открывается из истории и позволяет вернуться к списку. Данные целей и задач берутся из замороженного `HistoryItem`, а не из текущей комнаты.
- Пустая история, пустой фильтр, загрузка и ошибка с повтором. Loading/error доступны через явные инструменты демо, чтобы проверить состояния без сервера; они не обозначают настоящую сетевую ошибку.
- Настройки сохраняют только несекретные адрес сервера и username в `%USERPROFILE%\.focusduo\preferences.properties`. Поддержаны default `http://127.0.0.1:8090`, приоритет `FOCUSDUO_BASE_URL`, проверка адреса и явный logout. Смена URL завершает текущий демовход и изолирует локальные аккаунты по адресу; демоданные серверу не отправляются. HTTP-реализация запланирована на этап 5.
- Незавершённый ввод настроек и форм не перезаписывается при обновлении комнаты. Автоматический итог открывается только на главной/в комнате без активного диалога; на остальных экранах показывается уведомление и новый результат становится доступен в истории. Ограничения длины auth/profile/goal/task согласованы по Unicode code points.

## База из этапов 1–3

- Самостоятельная desktop-сборка: Kotlin/JVM 2.2.20, Compose Desktop 1.9.1, Gradle Wrapper 8.13 с SHA-256 и Java toolchain 21. PowerShell-скрипт находит JDK 21 без изменения постоянных системных настроек.
- Светло-зелёные компоненты Compose, Manrope с кириллицей, согласованные Canvas-иконки, системная рамка Windows. Комната сохраняет круговой таймер слева, участников под ним и карточки задач справа; узкое окно использует одну колонку и прокрутку.
- Явное включение демо через `--demo` или стартовый экран. В заголовке окна и интерфейсе видна пометка режима; серверные соединения не создаются.
- `FocusDuoRepository`, локальный `FakeRepository` и `StateFlow`. Изменения сериализуются через `Mutex`; снимки и история содержат неизменяемые списки.
- Создание пустой комнаты, вход в подготовленный пример `FD-DEMO42`, приглашение и копирование кода через clipboard. Локальный пример открывается от имени обычного участника; для управления таймером можно переключиться на создателя.
- Собственная цель до 240 символов; добавление, редактирование, отметка и удаление собственных задач. Название после trim содержит 1–160 символов; максимум 20 задач у каждого участника. Чужие задачи доступны только для чтения, в том числе владельцу комнаты.
- Настройки длительности: фокус 5–180, перерыв 1–60 целых минут. Их меняет только создатель вне RUNNING/PAUSED.
- FOCUS запускается владельцем при двух участниках и отсутствии активного раунда. BREAK запускается отдельно после текущего COMPLETED FOCUS. Следующий рабочий раунд тоже запускается вручную.
- Отсчёт и круговой прогресс связаны со снимком репозитория. В демо монотонные часы защищают отсчёт от коррекции системного времени; UI регулярно запрашивает свежий снимок. Обычные тики обновляют временные поля без изменения revision.
- Пауза замораживает остаток и активное время, продолжение сохраняет исходный startedAt и устанавливает новый срок из остатка. Только владелец управляет раундом. Команды адресуют конкретный текущий roundId.
- Ручное завершение фиксирует COMPLETED/MANUAL и фактическое активное время без пауз. Автозавершение фиксирует COMPLETED/ELAPSED с endedAt, равным сроку окончания даже при поздней обработке. Завершение и историю создаёт `FakeRepository`, а не круговой индикатор.
- Итог показывает тип раунда, реальное активное время, плановую длительность, цели, задачи и счётчики обоих. У досрочного завершения, окончания по времени и отмены разные подписи. История фиксирует копию один раз по roundId; дальнейшие изменения задач, целей и имён не меняют старый результат.
- Явное закрытие комнаты с подтверждением доступно обоим. Активный раунд становится CANCELLED/ROOM_CLOSED; уже завершённый результат сохраняется. Закрытая комната доступна для просмотра, её изменения запрещены; на главной можно создать новую комнату. Закрытие окна является отдельным действием приложения.
- В состоянии хранятся последние 50 результатов по endedAt и roundId. На этапе 3 был доступен отдельный итог; этап 4 добавляет общий список и детали. Это не статистика за всё время.
- Инструменты демо: присоединение партнёра, смена точки зрения, локальное имя, сброс с подтверждением, продвижение демочасов «+1 минута» и «До окончания раунда» во время RUNNING. Они не расширяют API и не отправляются серверу.

## Решения и границы

Рабочая ветка — `feat/desktop-mvp`, исходная база этапа 4 — пользовательский коммит `27b0b88` с результатом этапа 3. Изменения этого этапа находятся только внутри `desktop/**`; backend и общие файлы не меняются. Новые коммиты и удалённые push/merge/publish агентом не выполнялись.

Окончательный дизайн — [последний светло-зелёный макет пользователя](design/light-green-reference.png). Он заменяет тёмную тему из исходного ТЗ и общих `docs/design/`; контракт V1 сохраняется. Справочные копии полного ТЗ и контракта находятся в `desktop/docs/reference/`.

Демо моделирует локальный сервер и второго участника в одном процессе. Статус «В фокусе» определяется активным раундом; он не является online-присутствием или измерением внимания. Сброс демо удаляет локальную комнату и историю; закрытие комнаты сохраняет результат. Logout сохраняет деморепозиторий аккаунта и активный раунд до закрытия процесса. У реального backend закрытие приложения, logout и потеря сети не закрывают комнату; сетевая реализация клиента будет добавлена отдельно.

Общие [backend HANDOFF](../../docs/backend/HANDOFF.md) и [план совместной приёмки](../../docs/backend/INTEGRATION.md) прочитаны. Их «третий этап» относится к серверной подготовке и реальной интеграции, тогда как выполненный desktop-этап 3 добавлял локальный демо-таймер. Успешные серверные HTTP/WS-проверки не подтверждают работу Kotlin-клиента; Kotlin REST/WS, reconnect и LAN пока не запускались.

## Точные ограничения

1. Демоаккаунты, хеши демопаролей, комнаты и результаты хранятся только в памяти одного процесса. Перезапуск удаляет их; сброс удаляет комнату и результаты текущего демоаккаунта. Второй участник моделируется локально. Работа двух реальных клиентов ещё не реализована.
2. Вход/регистрация работают только в явном деморежиме. Настоящая авторизация и серверные сессии не подключены. Preferences сохраняют лишь URL и username; изменение имени в демо не является серверным редактированием профиля. История ограничена последними 50 раундами V1 без пагинации.
3. Нет `RealRepository`, Ktor, сериализации DTO, REST/WS, bearer-сессий, reconnect и обработки сетевых конфликтов. Настройка сервера — конфигурация для следующего этапа, сейчас адрес не используется для запросов. Автоматического переключения с реального сервера на fake нет.
4. Контрактные JSON-fixtures, серверный таймер, идемпотентность и совместная интеграция с Java этим клиентом ещё не проверялись. Монотонные часы и продвижение времени проверяют только демо; они не подтверждают синхронизацию реального клиента после сна или разрыва сети.
5. Новые экраны этапа 4 ещё не проверены запуском Compose: по просьбе пользователя этот аудит отложен до этапа 7. Полный аудит доступности и заключительная визуальная регрессия остаются в этапе 9. Используется системная рамка Windows; упаковка `.msi`/`.exe`, установка и подпись ещё не выполнены. Bash-команды README не проверялись на Linux/macOS.

## Коммит, push и PR

После просмотра результата выполнить в PowerShell по очереди. Если команда завершилась ошибкой, следующую не выполнять:

```powershell
Set-Location "C:\Users\user\Desktop\focusDuo"
git add -- desktop
git diff --cached --stat
git commit -m "feat(desktop): add demo authentication history and settings"
git push -u origin feat/desktop-mvp
```

Перед коммитом убедиться по списку staged-файлов, что включены только нужные desktop-изменения. Push отправляет рабочую ветку, без слияния в `main`. [Заголовок и описание PR этапа 4](PR_STAGE_4.md).
