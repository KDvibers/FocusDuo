# Этапы backend и контрольные PR

Репозиторий: [KDvibers/FocusDuo](https://github.com/KDvibers/FocusDuo). Для каждого этапа: подготовить изменения и проверки → создать локальный коммит → **владелец выполняет push** → открыть PR → пройти review и проверки. PR не объединяется автоматически; решение о merge принимает владелец. Новые backend-ветки используют `feat/`, без префикса `codex/`; названия прежних веток ниже сохранены как история. Существующие изменения сохраняются, `desktop/` изменяет только Kotlin-разработчик.

**Итог версии 0.1.0: согласованный объём этапов 1–4 завершён по решению владельца после подтверждения работы приложения.** Основной совместный сценарий принят в объёме [удалённой проверки](REMOTE_ACCEPTANCE_2026-10-12.md), объединённой в PR #21. Windows x64 MSI собран, проверки первого ПК записаны в [desktop-протоколе](../../desktop/docs/WINDOWS_PACKAGING.md), второго ПК и общее подтверждение пользователя — в [итоговом отчёте пакета](WINDOWS_PACKAGE_ACCEPTANCE.md). Это завершение согласованной версии, а не новый PASS всех вариантов матрицы: исторические записи сохраняют свои версии и ограничения. Push и создание финального PR выполняет пользователь; публикация MSI остаётся отдельным решением.

Включает Flyway, Maven Wrapper, Compose, backend CI, необходимые тесты и документацию запуска/контракта.

Состояние: первый PR `feat/backend-mvp` → `main` объединён, базовый commit `main` — `462b827`. Локально прошли 40 тестов с нативным PostgreSQL 17.11 и HTTP-проверка собранного JAR. По [отчёту Kotlin-разработчика](../../desktop/docs/WINDOWS_PACKAGING.md) получен Windows x64 MSI `0.1.0` со встроенным Java runtime, иконкой и ярлыками рабочего стола/меню «Пуск». В отчёте записан новый прогон 199 тестов без ошибок и пропусков; здесь эти тесты повторно не запускались. EXE не заявляется. Backend и PostgreSQL продолжают работать отдельно.

[Итоговый отчёт MSI](WINDOWS_PACKAGE_ACCEPTANCE.md) подтверждает установку того же артефакта на втором ПК, запуск обоими ярлыками и использование встроенного runtime. Общее подтверждение пользователя завершает согласованную приёмку версии, но не подменяет отдельный протокол каждого installed HTTPS/WSS-сценария или ошибки сети. Чистая Windows без отдельного JDK/Gradle остаётся `NOT_RUN`: запуск с пустым `JAVA_HOME` и без JDK в `PATH` подтверждает использование встроенного runtime, но не чистую систему. Удаление через Параметры Windows на втором ПК и обновление на другую версию также не проверены. [Исходное задание](WINDOWS_PACKAGING_HANDOFF.md) сохранено для справки; [инструкция подключения](SERVER_CONNECTION.md) описывает использование общего сервера.
