# FocusDuo Desktop — текущая передача

## Статус на 10 октября 2026

**Этап 3 из 10 завершён:** демо-таймер, пауза, продолжение, завершение, перерыв, закрытие комнаты и итог сессии. Этапы 1–2 завершены ранее; [план всей desktop-части](ROADMAP.md) сохраняет отдельные этапы для остальных экранов, сети, интеграции и упаковки.

## Что реализовано

- Самостоятельная desktop-сборка: Kotlin/JVM 2.2.20, Compose Desktop 1.9.1, Gradle Wrapper 8.13 с SHA-256 и Java toolchain 21. PowerShell-скрипт находит JDK 21 без изменения постоянных системных настроек.
- Светло-зелёные компоненты Compose, Manrope с кириллицей, согласованные Canvas-иконки, системная рамка Windows. Комната сохраняет круговой таймер слева, участников под ним и карточки задач справа; узкое окно использует одну колонку и прокрутку.
- Явное включение демо через `--demo` или стартовый экран. В заголовке окна и интерфейсе видна пометка режима; серверные соединения не создаются.
- `FocusDuoRepository`, локальный `FakeRepository` и `StateFlow`. Изменения сериализуются через `Mutex`; снимки и история содержат неизменяемые списки.
- Создание пустой комнаты, вход в подготовленный пример `FD-DEMO42`, приглашение и копирование кода через clipboard. Локальный пример открывается от имени обычного участника; для управления таймером можно переключиться на создателя.
- Собственная цель до 240 символов; добавление, редактирование, отметка и удаление собственных задач. Название после trim содержит 1–160 символов; максимум 20 задач у каждого участника. Чужие задачи доступны только для чтения, в том числе владельцу комнаты.
- Настройки длительности: фокус 5–180, перерыв 1–60 целых минут. Их меняет только создатель вне RUNNING/PAUSED.
- FOCUS запускается владельцем при двух участниках и отсутствии активного раунда. BREAK запускается отдельно после текущего COMPLETED FOCUS. Следующий рабочий раунд тоже запускается вручную.
- Отсчёт и круговой прогресс связаны со снимком репозитория. В демо монотонные часы защищают отсчёт от коррекции системного времени; UI регулярно запрашивает свежий снимок. Обычные тики обновляют временные поля без изменения revision.
- Пауза замораживает остаток и активное время, продолжение сохраняет исходный startedAt и устанавливает новый срок из остатка. Только владелец управляет раундом. Команды адресуют конкретный текущий roundId.
- Ручное завершение фиксирует COMPLETED/MANUAL и фактическое активное время без пауз. Автозавершение фиксирует COMPLETED/ELAPSED с endedAt, равным сроку окончания даже при поздней обработке. Завершение и историю создаёт `FakeRepository`, а не круговой индикатор.
- Итог показывает тип раунда, реальное активное время, плановую длительность, цели, задачи и счётчики обоих. У досрочного завершения, окончания по времени и отмены разные подписи. История фиксирует копию один раз по roundId; дальнейшие изменения задач, целей и имён не меняют старый результат.
- Явное закрытие комнаты с подтверждением доступно обоим. Активный раунд становится CANCELLED/ROOM_CLOSED; уже завершённый результат сохраняется. Закрытая комната доступна для просмотра, её изменения запрещены; на главной можно создать новую комнату. Закрытие окна является отдельным действием приложения.
- В состоянии хранятся последние 50 результатов по endedAt и roundId. Полного экрана списка истории пока нет; текущий результат открывается отдельно. Это не статистика за всё время.
- Инструменты демо: присоединение партнёра, смена точки зрения, локальное имя, сброс с подтверждением, продвижение демочасов «+1 минута» и «До окончания раунда» во время RUNNING. Они не расширяют API и не отправляются серверу.

## Решения и границы

Рабочая ветка — `feat/desktop-mvp`, исходная база этапа — merge-коммит `04e699d` из `origin/main`. Он включает desktop PR #5 и backend PR #4. Изменения этого этапа находятся только внутри `desktop/**`; backend и общие файлы не меняются. Новые коммиты и удалённые push/merge/publish агентом не выполнялись.

Окончательный дизайн — [последний светло-зелёный макет пользователя](design/light-green-reference.png). Он заменяет тёмную тему из исходного ТЗ и общих `docs/design/`; контракт V1 сохраняется. Справочные копии полного ТЗ и контракта находятся в `desktop/docs/reference/`.

Демо моделирует локальный сервер и второго участника в одном процессе. Статус «В фокусе» определяется активным раундом; он не является online-присутствием или измерением внимания. Сброс демо удаляет локальную комнату и историю; закрытие комнаты сохраняет результат. У реального backend закрытие приложения, logout и потеря сети не закрывают комнату; сетевая реализация клиента будет добавлена отдельно.

Общие [backend HANDOFF](../../docs/backend/HANDOFF.md) и [план совместной приёмки](../../docs/backend/INTEGRATION.md) прочитаны. Их «третий этап» относится к серверной подготовке и реальной интеграции, тогда как текущий desktop-этап 3 является локальным демо. Успешные серверные HTTP/WS-проверки не подтверждают работу Kotlin-клиента; Kotlin REST/WS, reconnect и LAN пока не запускались.

## Точные ограничения

1. Демо хранится только в памяти одного процесса. Перезапуск или сброс удаляет комнату, задачи и результаты; второй участник моделируется локально. Работа двух реальных клиентов ещё не реализована.
2. Нет полного экрана истории, настоящих форм входа/регистрации и общих настроек сервера. В состоянии сохранены последние 50 результатов, но экран итога не заменяет общий список истории. Изменение имени в демо не является серверным редактированием профиля.
3. Нет `RealRepository`, Ktor, сериализации DTO, REST/WS, bearer-сессий, reconnect и обработки сетевых конфликтов. Будущий default сервера — `http://127.0.0.1:8090`; сейчас адрес не используется. Автоматического переключения с реального сервера на fake нет.
4. Контрактные JSON-fixtures, серверный таймер, идемпотентность и совместная интеграция с Java этим клиентом ещё не проверялись. Монотонные часы и продвижение времени проверяют только демо; они не подтверждают синхронизацию реального клиента после сна или разрыва сети.
5. Полный аудит доступности и будущих экранов остаётся в плане. Используется системная рамка Windows; упаковка `.msi`/`.exe`, установка и подпись ещё не выполнены. Bash-команды README не проверялись на Linux/macOS.

## Коммит, push и PR

После просмотра результата выполнить в PowerShell по очереди. Если команда завершилась ошибкой, следующую не выполнять:

```powershell
Set-Location "C:\Users\user\Desktop\focusDuo"
git add -- desktop
git diff --cached --stat
git commit -m "feat(desktop): add demo rounds timer and session results"
git push -u origin feat/desktop-mvp
```

Перед коммитом убедиться по списку staged-файлов, что включены только нужные desktop-изменения. Push отправляет рабочую ветку, без слияния в `main`. [Заголовок и описание PR этапа 3](PR_STAGE_3.md).
